Publicering av webbplatsen

Här beskriver jag hur webbplatsen publiceras på internet med hjälp av publiceringsplattformen Netlify.

Vad innebär publicering?

När en webbplats är färdigutvecklad behöver den publiceras för att andra ska kunna besöka och använda den via internet. Det innebär att webbplatsens filer placeras på en webbserver som gör dem tillgängliga genom en webbadress.

Det finns flera olika tjänster som erbjuder webbpublicering. För den här webbplatsen har jag valt att använda Netlify, eftersom plattformen gör det enkelt att publicera statiska webbplatser utan att behöva hantera en egen webbserver.

Netlify

Netlify är en plattform för att bygga, driftsätta och publicera webbplatser. Den kan bland annat användas för statiska webbplatser som består av HTML, CSS och JavaScript.

En fördel med Netlify är att plattformen kan kopplas direkt till ett GitHub-repository. När ändringar skickas till repositoryt kan Netlify automatiskt bygga och publicera den uppdaterade webbplatsen.

Netlify erbjuder även en webbadress till den publicerade webbplatsen, vilket gör det enkelt att dela den med andra.

Hur publiceringen går till

Publiceringen av den här webbplatsen görs i flera steg:

  1. Webbplatsens filer skapas och testas lokalt på datorn.
  2. Projektet laddas upp till ett GitHub-repository.
  3. GitHub-repositoryt kopplas till ett konto på Netlify.
  4. Netlify konfigureras så att webbplatsens HTML-filer och tillhörande mappar publiceras från projektets rotmapp.
  5. Netlify publicerar webbplatsen och skapar en webbadress där den kan besökas.

När projektet är kopplat till GitHub kan framtida ändringar publiceras automatiskt när den uppdaterade koden skickas till repositoryt.

Fördelar och nackdelar

Fördelar

  • Enkelt att komma igång och publicera webbplatser.
  • Kan kopplas direkt till GitHub.
  • Automatiska uppdateringar när projektet ändras.
  • Erbjuder en webbadress för den publicerade webbplatsen.
  • Det behövs ingen egen webbserver för enklare statiska webbplatser.

Nackdelar

  • Vissa funktioner och resurser kan vara begränsade beroende på abonnemang.
  • Det krävs ett konto för att använda plattformen.
  • Inställningarna kan kännas ovana i början.
  • Man är beroende av en extern tjänst för att webbplatsen ska vara tillgänglig.

Min erfarenhet

Jag valde Netlify eftersom det är en smidig lösning för att publicera en webbplats som denna. Möjligheten att koppla plattformen till GitHub gör det enkelt att hålla webbplatsen uppdaterad utan att behöva ladda upp filerna manuellt varje gång.

Det är också praktiskt att kunna testa webbplatsen lokalt innan ändringarna publiceras. På så sätt kan jag kontrollera att både innehåll och layout fungerar som de ska innan den uppdaterade versionen blir tillgänglig på internet.

Den publicerade webbplatsen

När webbplatsen är publicerad kan den besökas via sin Netlify-adress.
